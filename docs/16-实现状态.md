## 3. 已实现的安全机制（可在代码里核验）

设计文档里的安全要求，有一部分已经写进内核代码了。这些**可以直接审代码**：

| 机制 | 代码位置 | 验证方式 |
|---|---|---|
| 未声明权限的调用被拒 | `plugin/permission.go` | 读 `RequirePermission` |
| 未配置认证器时，需鉴权路由返回 500 而非放行 | `httpapi/server.go` `authenticate()` | 读代码，注释里写了理由 |
| 代理场景下 IP 取值（不无条件信任 XFF） | `httpapi/server.go` `ClientIP()` | 传 `trustProxy=false` 时永远用 RemoteAddr |
| JSON 拒绝未知字段 | `httpapi/response.go` `DecodeJSON()` | `DisallowUnknownFields` |
| 请求体大小限制 | 同上 | 默认 1 MB |
| 密钥不足 32 字节拒绝启动 | `config/config.go` `Validate()` | 有明确错误信息 |
| 空管理员密码拒绝启动 | 同上 | — |
| 单实例锁启动期硬失败 | `assemble/assemble.go` §9 | 有测试覆盖 |
| 插件清单未知字段报错 | `plugin/manifest.go` | `KnownFields(true)` |
| 插件 ID 字符集限制（防表名注入） | `plugin/manifest.go` `idPattern` | 正则约束 |
| 路由重复注册被拒 | `httpapi/server.go` `SetRoutes()` | 记警告并跳过 |
| 限流桶过期清理 | `httpapi/limiter.go` | 每 5 分钟 GC |
| 调度任务 panic 隔离 | `schedule/scheduler.go` `execute()` | 有 recover |
| 迁移版本号重复报错 | `store/store.go` | 有测试覆盖 |

**未落地的安全机制**（只在文档里）：出站校验 `ValidateOutboundURL`、备份加密、密码指纹 `pwd_sig`、反枚举的具体实现、行为风控。这些依赖尚未编写的业务插件。

## 4. 如何验证当前状态

```bash
# 在项目根目录执行

# 编译
go build ./...            # 应当通过

# 静态检查
go vet ./...

# 测试（含竞态）
go test ./... -race       # 只有 assemble 包有测试，其余显示 "no test files"

# 迁移验证（三种场景）
./scripts/test-migrations.sh

# 内核纯度（不允许出现业务或外部系统名）
./scripts/check-kernel-purity.sh

# 文档内部链接
./scripts/check-docs.sh
```

**注意**：`go test ./...` 显示绿色的主要原因是大量包"没有测试文件"。这不代表代码质量好，只代表没被发现的问题还不少。真实覆盖率请以 [11 测试计划](11-测试计划.md) §3 列的 20 个必测场景为准——那些**一个都还没写**。

### 不必审的

- **竞品分析的细节实现**——`参考项目/` 里的代码是别人的，不必逐行看
- **未实现部分的具体写法**——比如 L1 脚本引擎怎么实现，接口还没冻结
- **文档的排版与措辞**——除非影响理解

### 最希望被挑战的五个问题

1. **内核抽象是否过度？** 有没有为了"将来可能需要"而引入的抽象？（[02](02-系统架构.md) §4）
2. **"资源是能力"这条公理成立吗？** 会不会导致资源侧的深度做不过专用工具？（[02](02-系统架构.md) §0）
3. **竞品结论是否属实？** 特别是"六个项目零个做到求片入库闭环"这类强判断。（[G4](../分析/G4-外围工具.md)）
4. **免费与收费的划分公道吗？** 会不会把该免费的东西划进了付费？（[15](15-开源与商业模型.md)）
5. **路线图排序合理吗？** M2 与 M3 是否该并行；M5 运维网络是否该更靠前？（[12](12-路线图.md)）
