# EmbyBox 设计文档 · 05 事件目录

> **这是全项目最重要的一份文档。**
>
> 想知道「EmbyBox 能被扩展成什么样」，读这一份就够了——不需要读内核源码。
>
> 本文件与代码中的事件常量表（`pkg/kernel/event/events.go`）**人工同步**：新增、更名或删除事件必须两处同改（第二轮 D09/D20——原"由代码自动生成、永不漂移"的声明与实现不符，已更正）。

---

## 1. 事件机制说明

### 1.1 为什么用事件而不是直接调用

插件之间**不应该互相认识**。求片插件不应该 import Telegram 插件。

它只需要在"求片创建成功"时抛出一个事件，谁关心谁订阅。这样：

- 拆掉 Telegram 插件，求片功能照常工作
- 加一个新通知渠道，不用改任何已有代码
- 想知道系统能扩展什么，读这一份文档即可

### 1.2 命名规范

```
<领域>.<实体>.<时机>
```

例如 `user.register.after`、`request.search.provide`。

**时机只有四个标准词**，每个的词义是固定的：

| 时机 | 语义 | 订阅者能否改变流程 | 典型用途 |
|---|---|---|---|
| `before` | 发生**前** | ✅ 可改写数据；返回错误可**中断**流程 | 校验、改写输入、拒绝操作 |
| `after` | 发生**后** | ❌ 返回错误只记日志，不影响其他订阅者 | 发通知、写日志、触发下游 |
| `check` | 校验点 | ✅ **投反对票**即否决 | 自定义规则、外挂认证源 |
| `provide` | 数据源征集 | ❌ 收集所有订阅者的结果，单个失败不影响其他 | 多源搜索、提供数据集 |

**理解这四个词的差别，就理解了整个扩展机制。**

### 1.3 订阅方式

```yaml
# L0 声明式插件
spec:
  hooks:
    - event: user.register.after
      template:
        notifier: telegram
        text: "欢迎 {{ .user.username }} 加入！"
```

```javascript
// L1 脚本插件
export default async function ({ event, ctx }) {
    const { user } = event.data;
    await ctx.notify.send({ channel: "telegram", to: user.telegram_id, text: `欢迎 ${user.username}` });
}
```

```go
// L2 原生插件
env.Bus.On(env.ID, event.UserRegisterAfter, 100, func(ctx context.Context, e *event.Event) error {
    user := e.Data["user"].(*identity.User)
    return notifyWelcome(ctx, user)
})
```

**通配订阅**：

| 模式 | 匹配 |
|---|---|
| `user.register.after` | 精确匹配 |
| `user.register.*` | 该前缀下的任意时机 |
| `user.*` | user 领域全部事件 |
| `user.**` | user 及其所有子层级 |
| `*` | 全部（慎用，噪音大） |

**优先级**：数值小的先执行，默认 100。`before` 型事件的优先级决定谁先有机会改写数据。

### 1.4 三条使用铁律

1. **`after` 型事件里不要做会影响主流程的事。** 用户注册成功了就是成功了，发欢迎消息失败不该让用户看到 500。
2. **`provide` 型事件必须捕获自己的异常。** 一个资源源挂了不能拖垮整条搜索链。
3. **不要在同一事件里既订阅又派发，会造成回环。** 需要级联就派发**不同**的事件。

## 3. 事件详解

### 3.1 用户域

---

#### `user.register.before`

**时机**：`before`　**可中断**：是

**Data（输入，可改写）**

| 字段 | 类型 | 说明 |
|---|---|---|
| `username` | string | 用户名，可改写 |
| `email` | string | 邮箱，可改写 |
| `invite_code` | string | 邀请码（如启用） |
| `client_ip` | string | 客户端 IP |
| `source` | string | 来源：`web` / `telegram` / `api` |

**Result（输出，可选）**

| 字段 | 说明 |
|---|---|
| `reject_reason` | 拒绝时填写，作为错误信息返回 |

**典型用法**

| 用途 | 实现方式 |
|---|---|
| 邮箱域名白名单 | 检查 `email` 域名，不在白名单则返回 error |
| 注册限流 | 按 `client_ip` 计数，超限则拒绝 |
| 用户名保留字 | 检查 `username` 是否在黑名单 |

```javascript
export default async function ({ event }) {
    const allowed = ["qq.com", "gmail.com", "outlook.com"];
    const domain = event.data.email.split("@")[1];
    if (!allowed.includes(domain)) {
        throw new Error("该邮箱域名不在允许列表内");
    }
}
```

**时机**：`check`　**可中断**：是

**Data**

| 字段 | 类型 | 说明 |
|---|---|---|
| `username` | string | 用户名 |

**Result**

| 字段 | 说明 |
|---|---|

| `user_id` | 校验通过时的用户 ID |
| `auth_type` | 认证方式标识 |

**典型用法**：接入 OIDC、Passkey、LDAP 等外部认证源。

**时机**：`after`　**可中断**：否

**Data**

| 字段 | 类型 | 说明 |
|---|---|---|
| `user_id` | string | |
| `session_id` | string | 新会话 ID |
| `auth_type` | string | 认证方式（password / oidc / passkey / ...） |

#### `user.policy.provide` ★

**时机**：`provide`　**可中断**：否

**Data**

| 字段 | 类型 | 说明 |
|---|---|---|
| `user` | object | 用户对象 |
| `server_id` | string | 目标媒体服务器 |
| `entitlements` | array | 用户持有的全部权益 |

**Result**

| 字段 | 说明 |
|---|---|
| `policy` | `contract.Policy` 对象 |

**这是"卖差价"的落地扩展点。** 订阅者在收到请求后，根据用户的会员档位计算出实际权限：

```javascript
export default async function ({ event }) {
    const { user, entitlements } = event.data;
    // 取等级最高的有效权益
    const active = entitlements
        .filter(e => e.is_active && new Date(e.starts_at) <= new Date() && (!e.expires_at || new Date(e.expires_at) > new Date()) && !e.revoked_at)  // 四个条件对应 user_entitlements 的 is_active / starts_at / expires_at / revoked_at
        .sort((a, b) => b.rank - a.rank)[0];

    return {
        policy: {
            disabled: false,
            can_login: true,
            libraries: active?.libraries ?? [],      // 空数组 = 不限制
            allow_download: active?.rank >= 2,
            allow_transcode: active?.rank >= 1,
            max_concurrent: active?.rank >= 2 ? 4 : 2,
            max_parental_rating: active?.rank >= 2 ? 0 : 14
        }
    };
}
```

**多个订阅者都返回 policy 时**：按优先级取第一个。内核内置的 identity 插件会在最低优先级提供一个默认策略作为兜底。

#### `media.server.degraded` ★

**时机**：`after`　**可中断**：否

**Data**

| 字段 | 类型 | 说明 |
|---|---|---|
| `server_id` | string | |
| `reason` | string | 降级原因 |
| `previous_status` | string | 原健康状态 |
| `current_status` | string | 新健康状态 |

**这就是"降级必须可见"的落地方式。** 内核在探测到媒体服务器不可用时派发它，通知插件负责告警，监控插件负责计入指标。

> 竞品实测中，数据取不到时静默返回空，用户看到"暂无数据"而不知道是坏了。EmbyBox 要求所有降级路径都派发这个事件。

### 3.3 播放域

#### `playback.report.provide`

**时机**：`provide`　**可中断**：否

**Data**

| 字段 | 类型 | 说明 |
|---|---|---|
| `from` | time | 起始时间 |
| `to` | time | 结束时间 |
| `user_id` | string | 可选，指定用户 |

**Result**

| 字段 | 说明 |
|---|---|
| `records` | `[]PlaybackRecord` |
| `source` | 数据来源标识 |
| `complete` | bool，数据是否完整（用于降级判定） |

**典型用法**：三种数据源各注册一个订阅者，内核按优先级择优。

| 数据源 | 特点 |
|---|---|
| 统计插件（Playback Reporting） | 唯一能出真实历史时长与趋势的路径；需装插件 |
| 原生聚合端点 | 秒级，但只有"此刻"没有"过去" |
| 自建落库 | 业务数据可靠，但需要事件驱动持续采集 |

> **未装统计插件时**，相关模块应**整体降级隐藏**而不是显示 0 —— 显示 0 会让用户以为"我没看过片"。

#### `request.search.provide` ★

**时机**：`provide`　**可中断**：否

**Data**

| 字段 | 类型 | 说明 |
|---|---|---|
| `title` | string | 标题 |
| `year` | string | 年份 |
| `media_type` | string | movie / tv |
| `season` | int | 季 |
| `episode` | int | 集 |

**Result**：`resources`（`[]Resource`）

**这是多源搜索的落地方式。** 每个资源提供者注册一个订阅者，并发执行、结果合并、按 score 排序择优。

```javascript
export default async function ({ event, ctx }) {
    const { title, year } = event.data;
    const resp = await ctx.http.get("https://api.example.com/search", {
        params: { q: title, year }, timeout: 8000
    });
    return {
        resources: resp.data.items.map(it => ({
            provider: "my-source",
            title: it.name,
            size: it.size_bytes,
            seeders: it.seeders,
            quality: it.resolution,
            magnet: it.magnet,
            score: it.seeders * 2 + (it.resolution === "2160p" ? 50 : 0)
        }))
    };
}
```

> **必须捕获自身异常**。一个资源源超时不能拖垮整条搜索链，内核会跳过失败者继续收集其他源。

#### `request.acquire.after`

**时机**：`after`　**可中断**：否

**Data**

| 字段 | 类型 | 说明 |
|---|---|---|
| `request` | object | 求片工单 |
| `resource` | object | 资源 |
| `task_id` | string | Provider 返回的受理任务 ID |
| `accepted` | bool | 是否受理成功 |

**典型用法**：记录受理回执、启动进度轮询。

#### `request.complete.check`

**时机**：`check`　**可中断**：是（否决语义见下）

**Data**：`request`、`matched_item`
**Result**：`completed`（bool）、`message`

**典型用法**：自定义"什么算真的入库了"（如要求至少一个可播放的媒体文件）。

> **归并规则**：`check` 时机的通用语义是"投反对票即否决"（§1.2），本事件同样可中断——此前的"可中断：否"与通用语义矛盾，已更正（第二轮 D15）。否决只允许在**可信 scope 成立后显式投出**：受信回读确认实际媒体后，订阅者才可 deny；回读异常时工单保持待确认状态，不得自动判失败，也不得自动判完成。多个订阅者全票通过才算完成。

#### `resource.ingest.after` ★

**时机**：`after`　**可中断**：否

**Data**

| 字段 | 类型 | 说明 |
|---|---|---|
| `server_id` | string | 入库的服务器 |
| `item_id` | string | 媒体条目 ID |
| `item_name` | string | 条目名 |
| `tmdb_id` | string | 解析出的 TMDB ID |
| `media_type` | string | |
| `season` | int | 解析出的季 |
| `episode` | int | 解析出的集 |

**这是求片闭环的关键节点。** 媒体服务器的入库 webhook 触发 → 派发此事件 → 求片插件订阅并匹配未完成工单 → 自动置完成 → 通知用户。

竞品实测中**六个开源项目零个做到这一步**，断点就在这里。

```go
env.Bus.On(env.ID, event.ResourceIngestAfter, 50, func(ctx context.Context, e *event.Event) error {
    reqs, err := repo.FindPendingByTMDB(ctx, e.Data["tmdb_id"].(string), e.Data["season"].(int))
    if err != nil { return err }
    for _, r := range reqs {
        if err := svc.Complete(ctx, r.ID, e.Data["item_id"].(string)); err != nil {
            env.Log.Warn("工单自动完成失败", "request", r.ID, "err", err)
        }
    }
    return nil
})
```

#### `points.change.before`

**时机**：`before`　**可中断**：是

**Data**：`user_id`、`delta`、`reason`、`balance_before`
**Result**：`reject_reason`

**典型用法**：防刷限额、风控拦截。

#### `points.change.after`

**时机**：`after`　**可中断**：否

**Data**

| 字段 | 类型 | 说明 |
|---|---|---|
| `user_id` | string | |
| `delta` | int | 实际变动值 |
| `balance_after` | int | 变动后余额 |
| `reason` | string | 与流水一致 |
| `ref_type` / `ref_id` | string | 关联对象 |

#### `order.create.before`

**时机**：`before`　**可中断**：是

**Data（输入，可改写）**

| 字段 | 类型 | 说明 |
|---|---|---|
| `user_id` | string | |
| `plan_id` | string | 套餐 |
| `plan_snapshot` | object | 套餐快照（可改写，如叠加优惠） |

#### `order.create.after`

**时机**：`after`　**可中断**：否

**Data**

| 字段 | 类型 | 说明 |
|---|---|---|

**时机**：`after`　**可中断**：否

**Data**

| 字段 | 类型 | 说明 |
|---|---|---|

| `payment` | object | 支付记录 |

## 4. 自定义事件

插件可以定义自己的事件：用 `<plugin-id>.<something>` 格式，避免与内核冲突。

```go
const EventScanFinished = "my-plugin.scan.finished"
env.Bus.Publish(ctx, &event.Event{Type: EventScanFinished, Source: env.ID, Data: ...})
```

**约定**：自定义事件不享受内核的时机语义（before/after/check/provide），由插件自行约定。

**建议**：自定义事件也应登记到插件文档里，方便使用者发现。

## 6. 设计检查清单

写插件时对照自查：

- [ ] 订阅的 `after` 事件里，我的失败不会影响主流程（不 return error 或用 `onError: continue`）
- [ ] 订阅的 `provide` 事件里，我捕获了全部异常并返回空结果
- [ ] `before` 事件里我只做校验，没有产生副作用
- [ ] 我没有在同一事件里既订阅又派发，造成回环
- [ ] 我的自定义事件用了 `<plugin-id>.` 前缀
- [ ] 我的处理是幂等的（事件可能重放）
- [ ] 我的 handler 有超时声明，不会长时间阻塞
