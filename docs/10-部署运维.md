# EmbyBox 设计文档 · 10 部署运维

> 目标：**一个二进制 + 一个数据库文件 + 一份配置，就能跑起来。**
> 不需要 Node、不需要 Redis、不需要在启动时联网。

---

## 1. 部署形态

### 1.1 三种

| 方式 | 适用 | 命令 |
|---|---|---|
| **裸二进制**（推荐） | 有 shell 的 VPS / NAS | `./embybox` |
| Docker | 群晖、威联通、不爱装东西的人 | `docker run ...` |
| Docker Compose | 搭配 PostgreSQL 的多实例部署 | `docker compose up -d` |

### 1.2 裸二进制

```bash
# 1. 下载（按平台选择）
curl -fL -o embybox https://github.com/<org>/embybox/releases/latest/download/embybox-linux-amd64
chmod +x embybox

# 2. 准备配置
mkdir -p data
cat > .env <<'EOF'
EMBYBOX_HTTP_ADDR=:8080
EMBYBOX_DB_DRIVER=sqlite
EMBYBOX_DB_DSN=./data/embybox.db
EMBYBOX_SECRET_KEY=<用下面的命令生成>
EMBYBOX_ADMIN_PASS=<初始管理员密码>
EOF

# 3. 生成密钥（32 字节以上）
echo "EMBYBOX_SECRET_KEY=$(head -c 32 /dev/urandom | base64)"

# 4. 启动
./embybox
```

**前端资源内嵌在二进制里**，不需要单独部署静态文件。

### 1.3 Docker

```bash
docker run -d \
  --name embybox \
  -p 8080:8080 \
  -v /path/to/data:/app/data \
  -e EMBYBOX_SECRET_KEY=<密钥> \
  -e EMBYBOX_ADMIN_PASS=<初始密码> \
  -e EMBYBOX_TIMEZONE=Asia/Shanghai \
  --restart unless-stopped \
  ghcr.io/<org>/embybox:latest
```

### 1.4 反代（推荐配置）

生产环境建议在 Nginx / Caddy 后面跑，由反代处理 TLS。

```nginx
server {
    listen 443 ssl http2;
    server_name emby.example.com;

    ssl_certificate     /etc/ssl/fullchain.pem;
    ssl_certificate_key /etc/ssl/privkey.pem;

    client_max_body_size 20m;

    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_http_version 1.1;

        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # SSE 推送需要关闭缓冲，否则事件会被攒着一起发
        proxy_buffering off;
        proxy_read_timeout 3600s;
    }
}
```

> **注意**：开了反代后必须设置 `EMBYBOX_TRUST_PROXY=true`，否则限流会把所有请求当成来自反代 IP。

## 2. 配置项全表

所有配置通过环境变量，前缀 `EMBYBOX_`。

### 2.1 服务

| 变量 | 默认 | 说明 |
|---|---|---|
| `HTTP_ADDR` | `:8080` | 监听地址 |
| `BASE_URL` | `http://localhost:8080` | 对外访问地址，用于生成回调链接 |
| `TIMEZONE` | `Asia/Shanghai` | **业务时区**。所有"今天""到期日""签到周期"都按它计算 |
| `TRUST_PROXY` | `false` | 是否信任 `X-Forwarded-For`。**反代后必须设为 true** |
| `METRICS_ADDR` | 空 | Prometheus 指标端口，空表示不开启 |

### 2.2 数据库

| 变量 | 默认 | 说明 |
|---|---|---|
| `DB_DRIVER` | `sqlite` | `sqlite` 或 `postgres` |
| `DB_DSN` | `./data/embybox.db` | SQLite 是文件路径；PG 是连接串 |

### 2.3 安全

| 变量 | 默认 | 说明 |
|---|---|---|
| `SECRET_KEY` | 空 | **主密钥，≥ 32 字节**。未设置时开发环境自动生成并告警，生产环境拒绝启动 |
| `SESSION_TTL` | `72h` | 会话有效期 |
| `ADMIN_USER` | `admin` | 初始管理员用户名 |
| `ADMIN_PASS` | 空 | 初始管理员密码。**留空则拒绝启动** |
| `TRUSTED_NETS` | 空 | 额外信任的代理网段（CIDR，逗号分隔） |

### 2.4 日志

| 变量 | 默认 | 说明 |
|---|---|---|
| `LOG_LEVEL` | `info` | `debug` / `info` / `warn` / `error` |
| `LOG_FORMAT` | `text` | `text` 或 `json`（生产建议 json，便于采集） |

### 2.5 插件与数据

| 变量 | 默认 | 说明 |
|---|---|---|
| `PLUGIN_DIRS` | `./plugins` | 插件搜索目录，逗号分隔 |
| `DISABLED_PLUGINS` | 空 | 显式禁用的插件 ID，逗号分隔 |
| `DATA_DIR` | `./data` | 数据目录（上传、备份、插件数据） |

### 2.6 安全实践

```bash
# ❌ 错误：把密钥写在 docker-compose.yml 里提交到 git
environment:
  - EMBYBOX_SECRET_KEY=abc123

# ✅ 正确：用 env_file，且 .env 在 .gitignore 里
env_file:
  - .env
```

## 3. 首次启动

启动时按顺序执行：

```
1. 读取并校验配置
   └─ 配置非法 → 打印明确原因 → 退出（不带着错误配置硬跑）

2. 打开数据库连接
   └─ 建目录、开 WAL、开外键约束

3. 执行内核迁移（版本 1-999）

4. 发现插件
   └─ 内置插件 + 扫描 PLUGIN_DIRS
   └─ 单个插件加载失败只告警，不阻断启动

5. 拓扑排序（按 requires）

6. 逐个 Register
   └─ 注册能力、订阅事件、声明迁移

7. 执行插件迁移（版本 1000+）

8. 单实例锁自检
   └─ 拿不到锁 → 打印原因 → 退出

9. 创建管理员（仅首次）
   └─ 打印初始密码到日志，并提示尽快修改

10. 启动 HTTP 服务
11. 启动调度器
12. 派发 system.startup
```

**启动完成的日志**（这是排障时的第一手信息）：

```json
{"level":"INFO","msg":"装配完成","插件数":6,"声明式插件数":0,"能力数":3,"事件订阅数":14,"警告数":0}
{"level":"INFO","msg":"HTTP 服务已启动","addr":"[::]:8080","base_url":"http://localhost:8080"}
{"level":"INFO","msg":"调度器启动","任务数":4,"扫描间隔":"5s"}
```

**有警告时**（配置错误但可继续）：

```json
{"level":"WARN","msg":"插件 xyz 声明了内核不认识的权限：user.readd（可能是拼写错误）"}
```

## 4. 升级

### 4.1 步骤

```bash
# 1. 备份（必做）
./embybox backup --output /path/to/backup.zip

# 2. 替换二进制
systemctl stop embybox
curl -fL -o embybox.new <新版本地址>
chmod +x embybox.new
mv embybox.new embybox

# 3. 启动（迁移自动执行）
systemctl start embybox

# 4. 验证
curl -s localhost:8080/healthz
curl -s localhost:8080/readyz
journalctl -u embybox -n 50        # 看有没有迁移失败
```

### 4.2 迁移是自动的，但要理解它做了什么

- 迁移只前进，不会自动回滚
- 每个迁移在独立事务里执行（SQLite 的 DDL 无事务，逐语句执行并记录）
- **升级前务必备份**：迁移失败时唯一的恢复手段就是回退到备份

### 4.3 回滚

```bash
systemctl stop embybox
# 换回旧二进制
cp embybox.old embybox
# 恢复备份的数据库
./embybox restore --input /path/to/backup.zip
systemctl start embybox
```

> **注意**：如果新版本执行了不可逆的迁移（如删列），回滚旧版本可能启动失败。这就是为什么迁移规范要求"删列必须先停用至少一个版本"。

## 5. 备份与恢复

### 5.1 备份内容

| 内容 | 说明 |
|---|---|
| 数据库 | 全部业务数据 |
| 配置文件 | `.env`（不含密钥时可以单独存） |
| 上传文件 | `DATA_DIR` 下的用户上传 |
| 主密钥 | **必须单独安全保存**，丢了就解不开加密的凭据 |

### 5.2 备份命令

```bash
./embybox backup --output backup.zip --encrypt
```

备份文件包含：
- SQLite 数据库（用 `VACUUM INTO` 保证一致性快照，**不直接复制文件**）
- 清单（版本、时间、文件校验和）

### 5.3 恢复协议

**这是有回滚的协议，不是简单的覆盖：**

```
1. 校验备份文件的完整性与版本兼容性
2. 把当前数据库改名为 .restore-pending-<时间戳>
3. 解压备份到正式位置
4. 尝试启动（跑迁移）
5. 成功 → 删除 .restore-pending
   失败 → 自动回滚到 .restore-pending 并报错
```

**关键约定**：**提交结果不明确时，不自动重复导入**。这是从竞品的备份恢复文档中提炼的原则——恢复操作重复执行可能造成数据错乱。

### 5.4 定时备份

```bash
# crontab
0 4 * * * cd /opt/embybox && ./embybox backup --output /backup/embybox-$(date +\%F).zip --encrypt
```

保留策略建议：日备保留 7 份，周备保留 4 份，月备保留 6 份。

## 6. 监控

### 6.1 健康探针

| 端点 | 用途 | 行为 |
|---|---|---|
| `/healthz` | 存活 | 只说明进程还活着，不检查依赖。容器编排用它决定是否重启 |
| `/readyz` | 就绪 | 检查数据库等关键依赖。负载均衡用它决定是否摘流量 |

**两者的区别很重要**：数据库暂时不可用时，进程是活的（不该被重启），但不该接流量（该被摘掉）。

### 6.2 必须关注的指标

| 指标 | 含义 | 告警阈值建议 |
|---|---|---|
| `embybox_http_requests_total{status}` | 请求数与状态码分布 | 5xx 占比 > 1% |
| `embybox_http_duration_seconds` | 响应时间 | P95 > 2s |
| `embybox_media_server_health{server}` | 媒体服务器健康 | 非 healthy 持续 2 分钟 |
| `embybox_degraded_total{component}` | **降级事件计数** | 任何降级都该通知 |
| `embybox_job_failures_total{job}` | 任务失败 | 连续 3 次失败 |
| `embybox_policy_sync_pending` | 权限同步积压 | > 100 且持续增长 |
| `embybox_request_queue_depth` | 求片队列深度 | 持续增长 |
| `embybox_db_locked_total` | 数据库锁冲突（SQLite） | 增长快说明该换 PG |

> `embybox_degraded_total` 是本项目的特色指标。竞品实测中最大的问题是"出错了不吭声"，这个计数器就是对策：任何降级路径都必须计数并暴露。

### 6.3 日志采集

生产建议 `LOG_FORMAT=json`，直接送 Loki / ELK。

关键字段：`level`、`msg`、`request_id`、`plugin`、`user`、`err`。

## 7. 排障手册

### 7.1 启动失败

| 现象 | 原因 | 处理 |
|---|---|---|
| `SECRET_KEY 至少需要 32 字节` | 密钥太短 | 重新生成 |
| `ADMIN_PASS 至少需要 8 位` | 初始密码太短 | 改配置 |
| `unable to open database file` | 数据目录不存在或无权限 | 检查 `DB_DSN` 的父目录权限 |
| `迁移 N 执行失败` | 迁移脚本有问题或库结构被手工改过 | 看完整错误，恢复备份 |
| `插件 X 依赖的 Y 不存在` | 缺依赖 | 装 Y 或禁用 X |
| `检测到循环依赖` | 插件互相依赖 | 错误信息里会打印环上的路径 |
| `声明了 single-instance，但锁已被占用` | 有另一个实例在跑 | 停掉旧实例，或改为 multi-instance |
| 端口被占用 | 别的东西占了 8080 | 改 `HTTP_ADDR` |

### 7.2 运行期问题

| 现象 | 排查方向 |
|---|---|
| 用户说看不了 | 看用户详情 → 权益是否有效 → `policy_sync` 是否 pending → 媒体服务器是否健康 |
| 求片一直不动 | 看工单步骤流水，定位卡在哪一步；看任务 `last_error` |
| 收不到通知 | 检查渠道配置 → 手动 `Test` → 看 audit_log 里的通知记录 |
| 数据统计不准 | **先确认是不是降级了**（`degraded_total` 指标、UI 是否显示警告条） |
| 限流误伤 | 检查 `TRUST_PROXY` 是否配对；反代后没开会导致所有人共用一个 IP |
| 到期没封号 | 检查调度器的到期扫描任务是否 enabled、上次执行状态 |

### 7.3 常用诊断命令

```bash
# 系统信息
curl -s localhost:8080/api/v1/system/info | jq

# 扩展点清单（确认插件订阅了什么）
curl -s localhost:8080/api/v1/system/events | jq

# 已注册的路由
curl -s -H "Authorization: Bearer $KEY" localhost:8080/api/v1/admin/system/routes | jq

# 任务状态
curl -s -H "Authorization: Bearer $KEY" localhost:8080/api/v1/admin/jobs | jq

# 以 dry-run 跑一次到期扫描，看会影响谁
curl -s -X POST -H "Authorization: Bearer $KEY" -d '{"dry_run":true}' \
     localhost:8080/api/v1/admin/jobs/identity.expire-scan/run | jq
```

## 8. 常见问题

**Q：一定要装 MoviePilot 吗？**
不一定。求片功能需要至少一个资源提供者，MoviePilot 只是其中最成熟的一个。你可以自己写一个 L0/L1 插件接别的源，或者干脆不启用求片。

**Q：能同时管理多台媒体服务器吗？**
可以。每台服务器独立配置、独立健康检查、独立权限同步。

**Q：SQLite 够用吗？**
1000 用户、日常并发量下完全够用，而且备份就是一个文件。如果出现大量 `database is locked` 日志，或者要多实例部署，再切 PostgreSQL。

**Q：怎么迁移到 PostgreSQL？**
配置 `DB_DRIVER=postgres` 和连接串。当前版本需要导出导入，后续计划提供迁移工具。

**Q：能改端口吗？**
能，`HTTP_ADDR=:9000`。注意 `BASE_URL` 也要相应改，否则生成的回调链接会错。

**Q：忘记管理员密码了？**
```bash
./embybox admin reset-password --user admin --new-password <新密码>
```
（此命令需要能访问数据库文件，属于物理访问权限范畴）

**Q：插件装错了怎么卸？**
```bash
./embybox plugin disable <id>
# 数据默认保留；确实要清空时
./embybox plugin remove <id> --purge
```

**Q：日志里一直有 `database is locked`？**
SQLite 的并发写限制。降低写入频率，或切 PostgreSQL。

## 9. 运维检查清单

### 上线前

- [ ] `SECRET_KEY` 已设置为随机长串，且**已单独备份**
- [ ] `ADMIN_PASS` 足够强，且首次登录后已修改
- [ ] `TIMEZONE` 与实际运营地区一致
- [ ] 反代后已设置 `TRUST_PROXY=true` 且配置了 `TRUSTED_NETS`
- [ ] HTTPS 已配置（会话令牌不该走明文）
- [ ] 定时备份已配置并**验证过恢复流程**
- [ ] 日志级别不是 `debug`

### 日常

- [ ] 每周看一次任务失败列表
- [ ] 关注降级指标
- [ ] 定期检查磁盘占用（备份、日志、上传文件）
- [ ] 定期检查权限同步积压

### 升级前

- [ ] 已备份
- [ ] 已读 CHANGELOG 里的破坏性变更说明
- [ ] 已知悉迁移内容
