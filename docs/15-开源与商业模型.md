# EmbyOne 设计文档 · 15 开源与商业模型

> 这份文档是对社区的**正式承诺**。
> 核心功能永久免费，只对差异化的高级能力收费。已开源的部分不会收回。

---

## 1. 开源承诺

### 1.1 五条铁律

**一、核心功能永久免费，采用 AGPL-3.0 开源。**
不限用户数、不限站点数、不设功能阉割、不需要联网验证。

**二、已经开源的功能不会改成收费。**
如果 M5 完成时你在用，那 M5 的全部能力对你永远免费。

**三、不在开源版里留后门或隐藏开关。**
代码全部可见。没有任何"付费后才解锁"的逻辑藏在开源版里。

**四、不要求联网验证许可证。**
即使专业版，也优先考虑离线许可文件而非在线校验。你可以断网部署。

**五、许可证不会变更。**
已经以 AGPL 发布的版本永远是 AGPL。不会出现"某天突然改成闭源"。

### 1.2 为什么开源

三个理由，按重要性排序：

**第一，这个领域的基础设施不该被绑架。**
站主的数据是自己的，服务是自己的，凭什么要被一个商业产品的存亡决定自己的业务存续？这个圈子已经见过太多"用了三年的面板突然停更/涨价/跑路"。

**第二，开源是唯一能追上一个快速变化生态的方式。**
媒体服务器会升级、网盘会改协议、PT 站的验证会变。这些适配工作量大且琐碎，靠一个团队永远追不完——必须让用户自己写插件。

**第三，我们的差异化不在基础功能上。**
开号、到期、求片、统计这些东西，谁做都差不多。真正的门槛在**行为风控**和**多租户**这类需要特殊视角的能力上（见 §3）。

## 2. 免费与收费的完整划分

### 2.1 社区版（AGPL-3.0，永久免费）

| 能力域 | 具体功能 |
|---|---|
| **用户与账号** | 统一状态机、注册三档（开放/邀请/待审批）、多档权益、批量操作、账号生命周期 |
| **媒体服务器** | 多服务器、连接健康检查、片库同步、权限同步、补偿队列 |
| **粒度授权** | 按等级控制片库、线路、下载、转码、并发数、家长分级 |
| **到期与续费** | 自动扫描封禁、延长/指定日期/永久、续费提醒 |
| **求片** | 工单状态机、多源并发搜索、入库自动回流、进度可见、撤销返还、免费顶帖 |
| **播放统计** | 播放记录采集、观影报告、排行榜、缺集巡检 |
| **计费运营** | 套餐与订单、卡密批次体系、积分账本、邀请关系树、支付回调幂等 |
| **通知** | Telegram / 企业微信 / 钉钉 / 飞书 / 邮件 / 通用 Webhook |
| **运维** | 反向代理、线路调度、持续探活、流量配额、证书自动化、备份恢复 |
| **可观测** | 审计日志、指标端点、降级可见性、任务调度与 dry-run |
| **插件系统** | 四级插件模型、事件总线、插件市场、全部插件开发能力 |
| **界面** | 完整用户中心、完整管理后台 |

**一句话**：站主日常运营需要的一切，都在社区版里。

### 2.2 专业版（商业授权）

只包含**规模化运营才需要**的能力：

| 能力 | 为什么它属于高级功能 |
|---|---|
| **行为风控** | 基于播放行为基线识别自动化工具。需要同时掌握运营数据与行为特征，实现复杂且需要持续调优 |
| **多租户** | 一套系统服务多个独立站点，用户池与计费完全隔离。需要近乎所有表结构配合，工程量大 |
| **AI 能力** | 智能媒体识别、自动补货决策、自然语言运维。依赖大模型调用成本 |
| **高级数据洞察** | 跨服务器的聚合分析、自定义报表、数据导出 API |
| **企业特性** | SSO（LDAP/OIDC 对接）、审计增强、SLA 支持、专属渠道 |
| **优先支持** | 响应时效承诺 |

### 2.3 托管服务（【待定】）

很多站主不想自己运维服务器。是否提供官方托管是一个独立决策：

| 考虑 | 说明 |
|---|---|
| 支持 | 降低使用门槛，让不折腾的人也能用上 |
| 顾虑 | 涉及用户数据托管，责任重大；且与"数据是你自己的"理念有张力 |

**倾向**：提供，但严格限定为"代运维"，数据所有权完全归用户，且支持随时导出迁移。

## 3. 划分依据

### 3.1 为什么基础功能不收费

因为这些是**公共基础设施**：

- 每个站主都需要开号、到期、求片、统计
- 这些功能的技术难度不高，社区里已有多个开源实现
- 对它们收费等于对"用电脑要开机"收费

更重要的是：**收费会阻碍采用**。一个新手站主在还没体验到价值之前就被要求付费，他根本不会开始。而我们最需要的是有人用、有人反馈、有人写插件。

### 3.2 为什么高级功能可以收费

因为这些是**效率放大器**，而且只对特定人群有价值：

| 功能 | 谁会需要 | 为什么愿意付 |
|---|---|---|
| 行为风控 | 有 500+ 用户的站主 | 共享账号直接等于收入损失；人工巡查不可能 |
| 多租户 | 同时运营多个站的人 | 否则要部署多套系统，运维成本远高于付费 |
| AI 能力 | 追求自动化的人 | 节省大量人工决策时间 |

**关键**：这些能力不是"把基础功能砍一刀再卖给你"，而是**额外增加的价值**。

### 3.3 一个反例说明

我们**不会**这样做：

> ❌ 开源版只让管 50 个用户，付费版才能管更多

这是最令人反感的模式，因为它制造了人为的稀缺。用户的用户数是用户自己的业务规模决定的，跟我们的成本无关。

我们**会**这样做：

> ✅ 开源版管 5000 个用户也完全免费；只有行为风控这类需要额外投入的能力才收费

### 为什么不是现在

**因为基础功能还不完整。**

在基础能力残缺的时候就急着变现，会发生什么：

- 用户被收费劝退，没人用
- 没人用就没有反馈，产品做不对
- 做不对就更没人用——负向循环

**正确的顺序是**：先做完整、做好用、攒下用户，再谈商业化。

### 一个具体承诺

> **在 M5（运维网络）完成之前，本项目不会出现任何形式的付费墙。**
>
> 判断标准是 [路线图](12-路线图.md) 中 M5 的验收条件全部达成——尤其是"线路状态持续可见且真的影响调度"这一条。

## 5. 我们不会做的事

明确列出，避免将来被"灵活解释"。

| 不做 | 理由 |
|---|---|
| ❌ 把已开源的功能改成收费 | 这是背叛信任，且会让所有早期用户离开 |
| ❌ 在开源版里留后门或隐藏开关 | 代码可见，任何"付费解锁"逻辑都藏不住，也没必要藏 |
| ❌ 要求联网验证许可证 | 你可以断网部署；专业版优先用离线许可文件 |
| ❌ 限制用户数或站点数 | 用户的业务规模与我们无关 |
| ❌ 用开源版做诱饵 | 开源版必须是能独立使用的完整产品，不是试用版 |
| ❌ 收集用户数据 | 除了我们自己需要诊断的错误报告（可选发送），不收集任何业务数据 |
| ❌ 变更已发布版本的许可证 | AGPL 就是 AGPL |
| ❌ 把关键适配（如某网盘的对接）锁在付费版 | 基础对接能力属于基础设施 |

## 6. 常见疑问

**Q：既然是 AGPL，别人拿去卖怎么办？**
AGPL 要求基于它的网络服务必须开源。对方可以卖"部署服务"，但必须公开修改后的源码。这对我们不是威胁——我们卖的是专业版功能和托管服务，不是许可证独占。

**Q：专业版的代码开源吗？**
不开源。但我们会**保证社区版是可独立使用的完整产品**，而不是缺少关键能力的残废版。

**Q：如果我需要闭源集成怎么办？**
AGPL 要求你的集成代码也开源。如果这不可接受，可以购买商业授权——这也是专业版的一种形态。

**Q：会不会有一天停止开源？**
不会。§5 的承诺是公开的、可引用的。如果我们违背，任何人都可以 fork 最后一个 AGPL 版本继续维护。

**Q：我怎么知道某个功能将来会不会收费？**
看 [路线图](12-路线图.md)。**M0-M6 的所有功能都是免费的**，这是明确写死的。M7 之后新增的高级能力会先在文档里说明归属，而不是做完再说。

**Q：能不能赞助？**
可以，赞助不等于购买。赞助者不获得额外权利，但会出现在致谢名单里。

**Q：专业版定价多少？**
【待定】。定价要等 M5 完成后、了解了真实用户规模与运维成本再定。现在定价是拍脑袋。

| 项 | 说明 |
|---|---|
| **贡献的代码** | 采用 AGPL-3.0 授权（与项目一致） |
| **贡献者权益** | 社区版功能对贡献者同样免费（本来就免费） |

## 9. 一句话总结

> **基础功能是这个领域的公共基础设施，收费没有道理。**
> **高级功能是效率放大器，为它付费是合理的。**
> **在基础功能做完之前，我们不该谈钱。**
