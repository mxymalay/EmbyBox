# EmbyBox 设计文档 · 07 前端设计

> 前端分两块：面向用户的**用户中心**，面向站主的**管理后台**。
> 两者共用一个 SPA，靠路由与权限区分。

---

## 1. 技术选型

| 项 | 选择 | 理由 |
|---|---|---|
| 框架 | Vue 3 + `<script setup>` | 生态最成熟，社区插件作者上手成本最低 |
| 语言 | TypeScript（严格模式） | 接口字段多，类型能挡掉大量低级错误 |
| 构建 | Vite | 快，配置简单 |
| 路由 | vue-router（history 模式） | — |
| 状态 | Pinia，**只用三个 store** | 见 §4 |
| 样式 | Tailwind CSS + CSS 变量主题 | 原子类写布局，变量管主题 |
| 请求 | 薄封装 fetch（不引 axios） | 少一个依赖，拦截逻辑自己写更可控 |
| 图标 | 内联 SVG 组件集 | 不引图标库，避免几 MB 字体 |

**为什么不用 Element Plus 等组件库**：组件库会把视觉锁死，而插件作者可能想换皮；同时它的体积与定制成本都不低。改为自建约 25 个 headless 组件（§6）。

**前端资源通过 `embed` 打进二进制**，部署时不需要 Node 环境。开发期用 Vite dev server 代理到后端。

## 4. 状态管理（严格限定三个 store）

竞品实测中出现过「单行 JSONB 存全局状态导致 6000 行 God Object」的教训。前端同样要防这个。

| store | 职责 | 禁止 |
|---|---|---|
| `session` | 令牌、当前用户、权限判断 | 不存业务列表数据 |
| `ui` | 主题、侧边栏、全局 loading | 不存业务逻辑 |
| `toast` | 消息提示队列 | — |

**列表数据一律放页面组件内**，用 `composables/usePagination` 管理。这样卸载页面即释放，不会因为"全局缓存"导致数据陈旧。

**登录态失效的统一处理**（`api/client.ts`）：

```
响应 401 + kind=unauthenticated  → 清 session → 跳 /login 并带 returnUrl
响应 403 + kind=expired          → 跳 /profile?renew=1（★ 不是跳登录页）
响应 403 + kind=forbidden        → toast 提示，不跳转
响应 429                          → 读 X-RateLimit-Reset，提示并退避
```

**`expired` 与 `unauthenticated` 必须区分**——这是「过期用户仍能登录续费」在前端的落地。跳错页面会让用户以为账号丢了。

## 5. 插件 UI Schema 渲染器 ★

插件不写 HTML/CSS，返回一棵组件树，前端统一渲染。

### 5.1 页面描述格式

```json
{
  "type": "page",
  "title": "跨服同步",
  "blocks": [
    { "type": "alert", "tone": "warn", "text": "上次同步有 3 条冲突未解决" },
    { "type": "stat-row", "items": [
        { "label": "待同步用户", "value": "{{ stats.pending }}" },
        { "label": "最近同步",   "value": "{{ stats.last_at | relative_time }}" }
    ]},
    { "type": "form", "fields": [ { "$ref": "#/spec/config" } ],
      "actions": [ { "label": "保存", "method": "POST", "path": "/api/v1/plugins/x/config" } ] },
    { "type": "table",
      "source": "/api/v1/plugins/x/conflicts",
      "columns": [
        { "key": "username", "label": "用户", "sortable": true },
        { "key": "emby_value", "label": "Emby" }
      ],
      "rowActions": [
        { "label": "以 Emby 为准", "method": "POST",
          "path": "/api/v1/plugins/x/resolve", "body": { "userId": "{{ row.id }}" } }
      ],
      "empty": { "type": "empty", "text": "没有冲突" }
    }
  ]
}
```

### 5.2 支持的组件类型

| 类别 | 类型 |
|---|---|
| 布局 | `page` `section` `grid` `card` `tabs` `collapse` |
| 数据 | `stat-row` `table` `chart` `timeline` `key-value` `progress` |
| 表单 | `form` `field`（string/text/number/bool/enum/multiselect/duration/secret/object/list/file） |
| 反馈 | `alert` `empty` `loading` `skeleton` |
| 交互 | `button` `dropdown` `modal` `drawer` |
| 逃生舱 | `iframe`（URL）`spa`（独立构建产物） |

### 5.3 插槽

| 插槽 | 位置 | 面向 |
|---|---|---|
| `user.sidebar` | 用户中心侧边栏 | 用户 |
| `user.home.card` | 用户首页卡片位 | 用户 |
| `user.profile.section` | 个人中心区块 | 用户 |
| `admin.sidebar` | 后台侧边栏 | 管理员 |
| `admin.dashboard.card` | 后台仪表盘卡片位 | 管理员 |
| `admin.user.detail.tab` | 用户详情页标签 | 管理员 |
| `admin.request.detail.panel` | 求片详情侧栏 | 管理员 |
| `admin.settings.section` | 系统设置分区 | 管理员 |
| `user.bottomNav` | 移动端底部导航 | 用户 |

**插槽枚举以本表与 [06-插件规范](06-插件规范.md) §6.3 两处同改为准**，两边清单必须完全一致（第二轮 D08 冻结）；渲染器收到未知插槽名时拒绝注册并在装配期报错，不允许静默丢弃。

### 5.4 模板表达式

`{{ }}` 内支持取值、内置管道与三元：

```
{{ user.username }}                      取值
{{ stats.rate | percent }}               百分数
{{ stats.last_at | relative_time }}      "3 分钟前"
{{ stats.bytes | filesize }}             "1.2 GB"
{{ user.rank >= 2 ? "VIP" : "普通" }}     三元
{{ row.items | length }}                 长度
```

**安全约束**：表达式在**受限沙箱**内求值，只允许白名单管道；不允许函数调用、不允许访问 `window`、不允许字符串拼接构造 DOM。渲染时全部走 Vue 的文本插值，**禁止 `v-html`**。

## 6. 基础组件清单（headless）

自建约 25 个，不含业务语义：

| 组件 | 说明 |
|---|---|
| `UiButton` | 变体：primary / secondary / ghost / danger；尺寸：sm / md；支持 loading、disabled |
| `UiInput` `UiTextarea` | 带 label、错误提示、前后缀 |
| `UiSelect` `UiMultiSelect` | 支持搜索 |
| `UiSwitch` `UiCheckbox` `UiRadio` | — |
| `UiModal` `UiDrawer` | 焦点锁定、ESC 关闭、层级管理 |
| `UiConfirm` | 统一二次确认，**破坏性操作用 danger 语气** |
| `UiTable` | 排序、选择、空态、加载态、行操作 |
| `UiPagination` | 游标与页码两种模式 |
| `UiTabs` `UiCollapse` | — |
| `UiToast` | 队列式消息 |
| `UiBadge` `UiTag` | 状态标记 |
| `UiSkeleton` `UiEmpty` | 加载与空态 |
| `UiCard` `UiStat` | 展示容器 |
| `UiDatePicker` `UiDuration` | 时间输入 |
| `UiIcon` | 内联 SVG 集合 |

**统一约定**：
- 所有异步操作有 loading 态与失败提示，**不允许静默失败**
- 破坏性操作（删除、封禁、作废）必须二次确认，且确认文案说明后果
- 空态区分「确实没有数据」与「加载失败」——这是竞品通病的正面对策

## 7. 交互规范

### 7.1 三种空态

| 场景 | 展示 | 文案示例 |
|---|---|---|
| 确实没有数据 | `UiEmpty`，带引导操作 | "还没有求片记录" + [去求片] |
| 加载失败 | `UiEmpty` + 重试按钮，**红色提示** | "加载失败，请重试" + [重试] |
| 依赖降级 | `UiAlert` 警告条，数据仍展示 | "统计插件未安装，观影报告暂不可用" |

**绝不把"加载失败"显示成"暂无数据"。** 竞品实测中，数据取不到时静默返回空，用户以为真的没数据。

### 7.2 破坏性操作

```
普通操作：[取消] [确定]
破坏操作：[取消] [确认封禁]   ← 按钮文字明确说做什么，不用"确定"
不可逆操作：需要输入确认短语（如输入用户名）
```

### 7.3 表单

- 提交按钮在请求中禁用并显示 loading
- 字段级错误就地提示，不用全局 toast
- **服务端返回的 `kind` 映射为字段级错误**，仅当无法定位字段时才用全局提示

### 7.4 长任务

求片、批量操作等长任务用 SSE 推送进度，进度条展示**阶段名**而不是百分比：

```
✅ 已创建工单
✅ 搜索到 12 个候选
⏳ 正在获取资源…       ← 而不是 "处理中 45%"
```

## 8. 主题与设计系统

用 CSS 变量定义两套主题，Tailwind 通过 `theme.extend` 引用变量。

```css
:root {
  --bg-primary: #0b0b10;
  --bg-surface: #15151d;
  --bg-elevated: #1b1b25;
  --border-default: #ffffff14;
  --text-primary: #e8e8ef;
  --text-secondary: #8f96a6;
  --accent: #8b5cf6;
  --accent-hover: #a78bfa;
  --radius-card: 12px;
  --radius-control: 8px;
}
[data-theme="light"] { /* 覆盖 */ }
```

**约定**：业务组件**不允许写死颜色**，必须用变量。这样换皮只需要改一个文件。

主题切换在 `<html data-theme>` 上，用内联脚本在首屏前设置，避免闪烁（FOUC）。

## 9. 性能与可访问性

| 项 | 要求 |
|---|---|
| 首屏 JS | < 200 KB（gzip） |
| 路由懒加载 | 所有 `views/` 下的页面按路由分割 |
| 图片 | 海报走同源代理 + 懒加载 + 尺寸参数 |
| 列表 | 超过 100 条必须分页或虚拟滚动，**不允许全量渲染** |
| 键盘 | 所有交互元素可 Tab 到达，模态框支持 ESC |
| 对比度 | 正文对比度 ≥ 4.5:1 |
| 表单 | 每个输入有 `<label>` 关联 |
| 动效 | 尊重 `prefers-reduced-motion` |

## 10. 开发约定

- 组件文件名用 PascalCase，composable 用 `useXxx`
- **一个组件不超过 300 行**，超了就拆——这是"便于理解"的硬指标
- 请求逻辑放 `api/`，组件里不直接写 `fetch`
- 类型定义集中在 `types/api.ts`，与后端文档 [04-API规范](04-API规范.md) 对齐
- 禁止在模板里写复杂表达式，抽成 composable
- 所有面向用户的文案走统一文案文件，便于将来做多语言
