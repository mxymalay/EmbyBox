## 0. 30 分钟快速开始

```bash
# 1. 生成插件骨架
embyone plugin init my-notifier --kind L1

# 2. 目录长这样
my-notifier/
├─ plugin.yaml        # 清单：你在做什么、要什么权限、挂在哪里
├─ hooks/
│  └─ on-user-register.js
└─ README.md

# 3. 本地调试（热重载）
embyone plugin dev ./my-notifier

# 4. 打包发布
embyone plugin pack ./my-notifier      # 产出 my-notifier-1.0.0.zip
```

一份**能跑起来**的最小插件（L0，纯 YAML，不写一行代码）：

```yaml
apiVersion: embyone.io/v1
kind: Plugin
metadata:
  id: hello-notify
  name: 注册欢迎通知
  version: 1.0.0
spec:
  permissions:
    - notify.send
  hooks:
    - event: user.register.after
      template:                     # L0 用模板，不写代码
        notifier: telegram
        to: "{{ .user.telegram_id }}"
        text: "欢迎 {{ .user.username }} 加入！你的会员将于 {{ .user.expires_at }} 到期。"
```

**它做了什么**：订阅「用户注册完成后」事件，通过 TG 发一条欢迎消息。不需要知道 TG 怎么调、事件怎么派发、配置怎么存。

## 1. 四级插件模型

选哪一级，取决于你要写多少逻辑：

| 级别 | 组成 | 上手成本 | 能干什么 | 典型场景 |
|---|---|---|---|---|
| **L0** | `plugin.yaml` | 5 分钟 | 配置项、模板化事件响应、路由转发、定时 HTTP 调用 | 加通知渠道、加一个媒体服务器预设、转发 webhook |
| **L1** | `plugin.yaml` + `*.js` | 30 分钟 | L0 全部 + 事件钩子里写 JS、可读写插件自带 KV、可发 HTTP | 字段转换、条件过滤、自定义消息、轻量聚合 |
| **L2** | Go 源码 | 半天 | 全部能力 + 注册自带数据表 + 高性能路径 | 官方能力域、复杂业务 |
| **L3** | 任意语言 + RPC | 半天 | 全部能力（除自带表迁移） | 复用 Python 生态、爬虫、OCR、MoviePilot 对接 |

**决策树**：

```
需要对接一个新的外部系统？
├─ 只是 HTTP 接口转发/字段映射 ──────→ L0
├─ 需要一点判断逻辑 ────────────────→ L1
├─ 需要自己的数据表 + 复杂状态 ───────→ L2
└─ 已经有 Python 现成代码想复用 ──────→ L3
```

## 2. `plugin.yaml` 完整字段

```yaml
apiVersion: embyone.io/v1          # 必填，版本化协议
kind: Plugin                       # 必填

metadata:
  id: my-plugin                    # 必填，全局唯一，小写+连字符，决定表名前缀
  name: 我的插件                    # 必填，展示名
  version: 1.2.0                   # 必填，语义化版本
  author: yourname                 # 建议
  license: MIT                     # 建议
  homepage: https://...            # 可选
  description: >                   # 建议，会显示在插件市场
    一句话说清这个插件解决什么问题。
  icon: refresh                    # 可选，内置图标名或图标 URL
  tags: [sync, media]              # 可选，市场分类

spec:
  # ── 依赖 ────────────────────────────────
  requires:                        # 依赖其他插件，装配器做拓扑排序
    - { id: emby-provider, version: ">=1.0.0" }

  # ── 权限（运行时强制）──────────────────
  permissions:
    - media-server.read            # 能力域.动作
    - media-server.write
    - user.read
    - user.write
    - notify.send
    - http.outbound                # 出站请求（配合 allowed_hosts）
    - kv.read                      # 插件自带 KV
    - kv.write
    - db.migrate                   # 建表/改表（L2/L3 才需要）
    - schedule.register
    - route.register
    - ui.register

  allowed_hosts:                   # http.outbound 的白名单，必须精确到域名
    - api.themoviedb.org
    - image.tmdb.org

  # ── 配置项（前端自动渲染表单）───────────
  config:
    - key: api_key
      type: secret                 # secret 类型落库加密、界面掩码、日志脱敏
      label: API Key
      required: true
    - key: interval
      type: duration               # 支持 30s / 5m / 2h / 1d
      label: 同步间隔
      default: 30m
    - key: mode
      type: enum
      label: 工作模式
      options:
        - { value: auto,   label: 自动 }
        - { value: manual, label: 手动 }
      default: auto
    - key: enabled_regions
      type: multiselect
      label: 启用地区
      options: [ cn, us, jp, kr ]
      default: [ cn ]
    - key: advanced
      type: object                 # 嵌套表单
      label: 高级设置
      fields:
        - { key: timeout, type: duration, default: 15s, label: 超时 }
    - key: rules
      type: list                   # 可增删的列表
      label: 规则
      item:
        fields:
          - { key: match, type: string, label: 匹配 }
          - { key: action, type: enum, options: [keep, drop], label: 动作 }

  # ── 自带数据表（可选）──────────────────
  schema:
    version: 1                     # 递增即触发迁移
    tables:
      - name: mapping              # 实际表名 = plugin_my_plugin__mapping
        columns:
          - { name: emby_id,   type: text,    primary: true }
          - { name: jf_id,     type: text,    unique: true }
          - { name: synced_at, type: datetime }
        indexes:
          - { columns: [synced_at] }

  # ── 事件钩子 ──────────────────────────
  hooks:
    - event: user.register.after
      handler: ./hooks/welcome.js      # L1：指向脚本
      priority: 100                    # 越小越先执行，默认 100
      timeout: 10s
      onError: continue                # continue | abort

    - event: request.search.provide    # provide 型事件：收集所有插件的结果
      handler: ./hooks/search.js
      timeout: 30s

  # ── HTTP 路由 ─────────────────────────
  routes:
    - path: /api/plugins/my-plugin/status
      methods: [ GET ]
      handler: ./handlers/status.js
      auth: user                       # none | user | admin | apikey
    - path: /api/plugins/my-plugin/webhook
      methods: [ POST ]
      handler: ./handlers/webhook.js
      auth: none
      rateLimit: "60/m"                # 内置限流

  # ── 定时任务 ──────────────────────────
  jobs:
    - id: sync-loop
      schedule: "@every 30m"           # 或 cron: "0 */2 * * *"
      handler: ./jobs/sync.js
      timeout: 5m
      retry: { max: 3, backoff: exponential }
      singleton: true                  # 多实例部署时全局只跑一个

  # ── 前端 UI ───────────────────────────
  ui:
    - slot: admin.sidebar              # 见 §6 插槽清单
      label: 跨服同步
      icon: refresh
      page: ./ui/page.json             # 或内联
    - slot: user.bottomNav
      label: 我的同步
      page: ./ui/user-page.json

  # ── CLI 命令（可选）────────────────────
  commands:
    - name: sync-now
      description: 立即触发一次同步
      handler: ./commands/sync.js

  # ── 提供者注册（L3/L2 用）──────────────
  provides:
    - capability: notifier
      implementation: builtin         # builtin(L2) | rpc(L3)
      priority: 50
```

## 3. 能力接口（成为 Provider）

插件通过实现能力接口把自己变成系统的"器官"。按业务语义定义，不按外部系统。

```go
// ── 媒体服务器 ────────────────────────────
type MediaServer interface {
    Capability
    ServerInfo(ctx) (ServerInfo, error)
    Users(ctx) ([]MSUser, error)
    CreateUser(ctx, UserSpec) (MSUser, error)
    UpdateUser(ctx, userID string, patch UserPatch) error
    DeleteUser(ctx, userID string) error
    SetPolicy(ctx, userID string, p Policy) error
    Libraries(ctx) ([]Library, error)
    Items(ctx, libID string, page Page) ([]Item, error)
    ItemExists(ctx, itemID string) (bool, error)
    Playing(ctx) ([]Session, error)
    PlaybackHistory(ctx, from, to time.Time) ([]Record, error)
}

// ── 下载器 ────────────────────────────────
type Downloader interface {
    Capability
    Add(ctx, Torrent) (TaskID, error)
    List(ctx, TaskFilter) ([]Task, error)
    Get(ctx, TaskID) (Task, error)
    Remove(ctx, TaskID string, deleteFiles bool) error
    SavePaths(ctx) ([]string, error)          // 用于路径映射
}

// ── 资源提供者（求片链的核心接点）──────────
type ResourceProvider interface {
    Capability
    Search(ctx, Query) ([]Resource, error)     // 搜索候选
    Acquire(ctx, Resource) (AcquireID, error)  // 下载 or 转存
    Status(ctx, AcquireID string) (AcquireStatus, error)  // 进度
    Cancel(ctx, AcquireID string) error
}

// ── 通知渠道 ──────────────────────────────
type Notifier interface {
    Capability
    Send(ctx, Message) error
    Test(ctx) error
    Capabilities(ctx) NotifyCaps            // 支持 markdown/按钮/图片？
}

// ── 元数据源 ──────────────────────────────
type MetadataProvider interface {
    Capability
    Search(ctx, Query) ([]MediaMeta, error)
    Detail(ctx, MediaRef) (MediaMeta, error)
    Trending(ctx, mediaType string, limit int) ([]MediaMeta, error)
}

// ── 认证提供者 ────────────────────────────
type AuthProvider interface {
    Capability
    Verify(ctx, Credentials) (*Identity, error)   // 账号密码
    Redirect(ctx, state string) (url string, err error)  // OAuth
    Callback(ctx, code string, state string) (*Identity, error)
}

// ── 支付提供者 ────────────────────────────
type PaymentProvider interface {
    Capability
    CreateCheckout(ctx, Order) (CheckoutURL string, err error)
    VerifyWebhook(ctx, raw []byte, headers http.Header) (*PaymentEvent, error)
    Refund(ctx, OrderRef, amountCents int64) error
}

// ── 存储后端 ──────────────────────────────
type Storage interface {
    Capability
    Put(ctx, key string, r io.Reader) (url string, err error)
    Get(ctx, key string) (io.ReadCloser, error)
    Delete(ctx, key string) error
    SignedURL(ctx, key string, ttl time.Duration) (string, error)
}
```

**多实现与择优**：同类能力可以注册多个。系统在需要时通过 `Best()` 按 `priority` + 健康度选，也可由配置显式指定。

## 4. 事件目录（扩展点全集）

事件命名：`<领域>.<实体>.<时机>`。时机四选一：`before`（可改可拦）、`after`（副作用）、`check`（投票否决）、`provide`（收集数据源）。

**这张表就是"系统能被扩展成什么样"的完整答案。**

### 4.1 用户域

| 事件 | 时机 | 插件能做什么 |
|---|---|---|
| `user.register.before` | 可拦 | 校验邀请码、限制邮箱域名、限流防刷 |
| `user.register.after` | 副作用 | 发欢迎通知、初始化积分、建外部资源 |
| `user.login.before` | 可拦 | 二次验证、设备风控、封禁拦截 |
| `user.login.check` | 投票 | 外挂认证源（Emby/OIDC/Passkey） |
| `user.login.after` | 副作用 | 记录登录日志、更新最后活跃 |
| `user.expire.check` | 投票 | 自定义到期判定规则 |
| `user.policy.provide` | 数据源 | 提供权限策略（并发/片库/转码限制） |
| `user.deleted.after` | 副作用 | 清理关联数据、回收网盘资源 |

### 4.2 资源域

| 事件 | 时机 | 插件能做什么 |
|---|---|---|
| `media.identify.before` | 可改 | 修正标题解析、补全季集信息 |
| `media.identify.after` | 副作用 | 写入自定义元数据 |
| `media.library.sync.after` | 副作用 | 触发下游动作（如生成海报墙） |
| `request.create.before` | 可拦 | 校验配额、积分、重复求片 |
| `request.create.after` | 副作用 | 通知管理员、写入工单系统 |
| `request.search.provide` | 数据源 | **返回你自己的搜索结果**（并发收集） |
| `request.filter.check` | 投票 | 过滤不符合条件的资源 |
| `request.acquire.before` | 可改 | 替换资源、调整参数 |
| `request.acquire.after` | 副作用 | 记录来源、埋点 |
| `request.complete.check` | 投票 | 判定是否真的入库了 |
| `resource.ingest.after` | 副作用 | 入库后动作（生成 strm / 通知 / 补集） |

### 4.3 计费域

| 事件 | 时机 | 插件能做什么 |
|---|---|---|
| `order.create.before` | 可改 | 优惠券、折扣计算 |
| `order.create.after` | 副作用 | 通知、埋点 |
| `order.paid.after` | 副作用 | 发放权益、开号、通知 |
| `points.change.before` | 可拦 | 防刷、限额 |
| `points.change.after` | 副作用 | 审计、对账 |

### 4.4 播放域

| 事件 | 时机 | 插件能做什么 |
|---|---|---|
| `playback.report.provide` | 数据源 | **提供播放记录**（Emby/Jellyfin/MP/自建） |
| `playback.report.after` | 副作用 | 触发榜单刷新、异常检测 |
| `insight.dataset.provide` | 数据源 | 提供自定义统计数据集 |

### 4.5 系统域

| 事件 | 时机 | 插件能做什么 |
|---|---|---|
| `api.route.provide` | 数据源 | 注册 HTTP 路由 |
| `ui.page.provide` | 数据源 | 注册前端页面 |
| `schedule.job.provide` | 数据源 | 注册定时任务 |
| `notification.provide` | 数据源 | 注册通知渠道 |
| `command.provide` | 数据源 | 注册 Bot 命令 / CLI 命令 |
| `agent.tool.provide` | 数据源 | **把能力暴露给 AI Agent** |

> 完整事件列表在运行时可通过 `GET /api/system/events` 或 `embyone events list` 查看，且 `docs/EVENT-CATALOG.md` 由代码自动生成，永不漂移。

## 5. L1 脚本钩子写法

脚本运行在 **goja**（ES5.1 + 部分 ES6），沙箱内，只有白名单 API。

```javascript
// hooks/welcome.js —— 用户注册后发欢迎消息
export default async function ({ event, ctx }) {
    const { user } = event.data;

    // ctx 提供的能力（受 permissions 限制）
    const points = await ctx.plugins.billing.grantPoints(user.id, 100, "注册奖励");
    await ctx.notify.send({
        channel: "telegram",
        to: user.telegram_id,
        text: `欢迎 ${user.username}！已赠送 100 积分。`,
        buttons: [[{ text: "查看会员", url: "https://example.com/profile" }]]
    });

    // 插件自带 KV（namespace 自动隔离）
    await ctx.kv.set("last_welcome_user", user.id);
    ctx.log.info("welcome sent", { user: user.id, points });
    return { ok: true };
}
```

```javascript
// hooks/search.js —— 提供资源搜索结果（provide 型事件）
export default async function ({ event, ctx }) {
    const { query } = event.data;               // { title, year, type, season }

    const resp = await ctx.http.get("https://api.example.com/search", {
        params: { q: query.title, year: query.year },
        timeout: 8000                           // 出站域名必须在 allowed_hosts 里
    });

    // 返回数组 → 系统自动合并其他 Provider 的结果
    return resp.data.items.map(it => ({
        provider: "my-plugin",
        title: it.name,
        size: it.size_bytes,
        seeders: it.seeders,
        quality: it.resolution,
        magnet: it.magnet,
        score: it.seeders * 2 + (it.resolution === "2160p" ? 50 : 0)
    }));
}
```

**ctx API 速查**：

| 命名空间 | 用途 | 所需权限 |
|---|---|---|
| `ctx.http` | 出站 HTTP（白名单+超时+重试+限流） | `http.outbound` |
| `ctx.kv` | 插件自带 KV（读写、TTL、原子自增） | `kv.read` / `kv.write` |
| `ctx.db` | 插件自带表的 CRUD | `db.read` / `db.write` |
| `ctx.user` | 查用户、改用户、发权益 | `user.read` / `user.write` |
| `ctx.media` | 媒体服务器操作 | `media-server.*` |
| `ctx.notify` | 发通知 | `notify.send` |
| `ctx.points` | 积分操作 | `points.write` |
| `ctx.request` | 求片工单操作 | `request.write` |
| `ctx.plugins.<id>` | 调用其他插件暴露的能力 | 对方需声明 `exposes` |
| `ctx.log` | 结构化日志（自动带 plugin_id） | — |
| `ctx.config` | 读插件配置（secret 自动解密） | — |
| `ctx.publish` | 主动派发事件 | — |

**沙箱约束**：无 `require`、无文件系统、无进程、无网络（除 `ctx.http`）、CPU 5s / 内存 64MB 上限、死循环会被中断。

## 6. UI Schema 规范

## 7. 数据模型与迁移

### 7.1 表命名空间

**强制**：插件表名一律 `plugin_<id 中连字符替换为下划线>__<表名>`。

```
插件 id: emby-jellyfin-sync
表名:    plugin_emby_jellyfin_sync__mapping
```

好处：① 一目了然谁的表；② 卸载可精确清理；③ 迁移互不干扰。

### 7.2 L0/L1：`schema` 声明式

在 `plugin.yaml` 的 `spec.schema` 里写 DDL 子集，内核负责建表与**加列演进**（只支持安全操作：加列、加索引、加表；改类型/删列需升级为 L2 迁移）。

`version` 递增即触发比对与增量执行。

### 7.3 L2/L3：SQL 迁移目录

```
my-plugin/
└─ migrations/
   ├─ 0001_init.sql
   ├─ 0002_add_index.sql
   └─ 0003_backfill.sql
```

- 命名 `<序号>_<描述>.sql`，按序号升序执行，执行记录写入 `plugin_audit`
- 每个文件在独立事务里执行（SQLite 不支持 DDL 事务，降级为逐语句 + 记录）
- **PostgreSQL 下插件表落在独立 schema**（`plugin_<id>`），宿主的 `public` 不被污染

### 7.4 数据生命周期

| 操作 | 默认行为 | 可配置 |
|---|---|---|
| 停用插件 | 保留数据 | — |
| 卸载插件 | **保留数据**（表改名加 `_orphaned` 后缀） | `--purge` 才真删 |
| 重置插件 | 清空本插件数据，保留表结构 | 需二次确认 |

## 8. 权限与安全

### 8.1 权限清单是强制的

未声明的权限，调用直接失败并审计：

```json
{
  "ts": "2026-10-05T10:12:33Z",
  "level": "warn",
  "plugin": "my-plugin",
  "action": "permission.denied",
  "capability": "user.write",
  "method": "UpdateUser",
  "msg": "plugin has no grant for user.write"
}
```

### 8.2 出站网络白名单

`ctx.http` 只允许 `allowed_hosts` 里的域名（支持 `*.example.com`）。内网地址（`127.0.0.1`、`169.254.169.254`、`10.0.0.0/8` 等）**默认拒绝**，防止 SSRF。

### 8.3 L3 进程隔离

```
┌──────────┐   JSON-RPC over stdio    ┌────────────┐
│  宿主     │ ←──────────────────────→ │ 插件进程    │
│ (Go)     │                          │ (Python/…) │
└──────────┘                          └────────────┘
      │ 监控：CPU / 内存 / 超时 / 崩溃
      └─ 越界 → 熔断 → 自动重启（指数退避）
```

- 协议：`Content-Length` 分帧 + JSON-RPC 2.0（兼容 LSP 风格）
- 握手：`initialize` 上报 `capabilities` 与 `permissions`，宿主校验一致性
- 超时：每次调用默认 30s，可声明覆盖；超时不计入重试
- 限额：默认 CPU 1 核 / 内存 256MB（可配）
- 崩溃：自动重启，`crash_count` 超阈值则禁用并通知管理员

### 8.4 机密处理

`type: secret` 的配置项：落库 AES-GCM 加密（密钥来自主密钥）、界面掩码、日志自动脱敏、导出配置时自动剔除。

## 11. 最佳实践

1. **一个插件只做一件事**。想同时做同步和通知，拆成两个插件用事件协作
2. **权限最小化**。能只读就别写；`http.outbound` 精确到域名，不要 `*`
3. **配置项优先于硬编码**。凡是用户可能想改的，都做成 `config`
4. **用事件而不是直接调用**。依赖另一个插件的能力，优先订阅它的事件
5. **失败要能自愈**。`jobs` 里声明 `retry`；钩子 `onError: continue` 避免拖垮主流程
6. **日志带上下文**。`ctx.log.info("msg", {...})` 的第二个参数会被结构化索引
7. **写清楚 `description`**。插件市场里，这是一句话说服别人安装的唯一机会
8. **不要吞异常**。返回明确的 error，让上游能决策（拒绝/降级/重试）

## 12. 反模式（会被内核拒绝或审计点名）

| 反模式 | 为什么不行 |
|---|---|
| 插件里直接连数据库绕过 `ctx.db` | 越过权限与命名空间隔离，审计失败 |
| `allowed_hosts: ["*"]` | SSRF 风险，插件市场审核直接拒 |
| 在 `job` 里做超过 5 分钟的同步阻塞 | 占用 worker，应拆分为分页 + 断点续跑 |
| 把状态存在内存里（L2/L3） | 重启即丢，应落 `ctx.kv` 或自带表 |
| 订阅 `provide` 事件但抛异常 | 会拖慢整条链，必须 catch 并返回空数组 |
| 用插件 id 之外的表前缀 | 迁移冲突，内核启动时报错 |
